# Changelog

## [Unreleased]

### Added (post-parity feature wave)
- **NDJSON audit log** — new `AuditLogEnabled` (default `$false`) and `AuditLogFile` (default `<LogDir>\audit.log`) configuration keys. When enabled, security-relevant events (`AUTH_FAIL`, `IP_BLOCKED`, `RATE_LIMITED`) are appended to a separate file as one JSON object per line with the fixed schema `{ ts, event, identity, ip, path, detail }`. ISO-8601 timestamps with offset. Serialised via a dedicated Mutex (`Global\PoshWebserverAudit`) so audit-event bursts cannot block request-log writes. New `Write-AuditLog` function in the runspace + an inline mutex-protected write in the main-thread IP-filter branch.
- **Per-API-key rate-limiting** — new `RateLimitPerIdentity` configuration key (default `$false`, BC). When enabled, requests with a valid `X-Api-Key` are accounted against the key's label instead of the client IP, separating quotas when multiple clients share a NAT/proxy. Anonymous and wrong-key requests still hit the per-IP quota so brute-force protection is preserved. `Test-RateLimit` got an `-Identity` parameter; the request handler resolves the label early (before the auth block) via the same `Resolve-ApiKeyIdentity` helper to avoid a second key compare.
- **Multiple API-keys with labels** — new `ApiKeys` configuration key (`label → key` hashtable, defined via the external `config.psd1`). Each request now resolves to a labelled identity (`'ci'`, `'monitoring'`, `'basic:<user>'`, `'anonymous'`, or `'-'` on auth failure). The label is written into every log line (new column between `Status` and `RequestId` in Native format, `cs(identity)` in IIS-W3C) and stashed in `$script:authIdentity` for downstream features (per-key rate-limit, audit log, Prom metrics). Legacy single `$env:POSH_API_KEY` is auto-merged into `ApiKeys` under the `'default'` label — no client changes required. `Write-Log` signature extended with `-Identity` and `-ElapsedMs`; both auto-resolve from `$script:authIdentity` and the per-request stopwatch when omitted.
- **Brotli compression alongside GZIP** — new `BrotliEnabled` configuration key (default `$true`). When both Brotli and GZIP are server-enabled and the client advertises both, Brotli wins (~15-25 % smaller text payloads). Same eligibility gates as GZIP (`GzipMinBytes`, `GzipMaxBytes`, `GzipMimeTypes`). Implemented in both `Send-Response` and `Send-StaticFile`. `Content-Encoding: br` is emitted on the response; `Vary: Accept-Encoding` is set on static responses. Falls back to GZIP, then uncompressed.
- **External configuration file (`config.psd1`)** — opt-in override for the inline `$cfg` defaults. Default path: `<baseDir>\config.psd1`; override via the new `-ConfigFile` script parameter. Values from the file override defaults; missing keys keep their default. `Import-PowerShellDataFile` parses only static data (no script execution). Malformed files abort startup with a clear message. A documented sample lives at `config.psd1.example` in the repo root.

### Fixed (post-feature review pass)
- **Auth bypass via case-insensitive credential comparison** — PowerShell's `-eq` is case-insensitive on strings. Both the `X-Api-Key` check and Basic-Auth username/password used `-eq`, so a configured key `Abc123` also accepted `aBC123`. Switched all three checks to `[string]::Equals` with `StringComparison.Ordinal`. Effective keyspace restored to byte-exact.
- **Byte-range suffix `bytes=-N` returned wrong content** — `Send-StaticFile`'s range parser had unreachable suffix-range branch; `bytes=-100` was served as `bytes=0-100` (first 101 bytes) instead of the last 100. Rewritten as explicit if/else.
- **GZIP unbounded memory** — `Send-StaticFile` compressed eligible text payloads in memory without an upper cap. Added `GzipMaxBytes` (default 10 MB); larger files stream uncompressed.
- **CORS Origin echo with control characters** — wildcard+credentials mode echoed the client's `Origin` header into `Access-Control-Allow-Origin` unvalidated; a CR/LF in `Origin` would surface as an `ArgumentException` 500. Pre-validate against control characters and DEL.
- **BG-job + IP-filter log writes raced** — multiple background jobs wrote to `JobsLogFile` via `Add-Content` without synchronisation; the main-thread IP-filter rejection log bypassed `$script:logMutex`. Both now use named Mutexes (`Global\PoshWebserverJobsLog` for jobs, the existing `Global\PoshWebserverLog` for IP filter) so concurrent writes serialise.
- **PHP-CGI `Process.Start()` exception leaked to 500** — when `php-cgi.exe` is removed between startup validation and a request, `Start()` threw, the handler emitted a generic 500. Now returns a structured 502 with cleanup of the partial Process handle.
- **Three IDisposable leaks in error paths** — `ConvertTo-PoshApiXml` (`StringWriter` + `XmlTextWriter`), `Send-StaticFile` GZIP branch (`MemoryStream` outside try/finally), `Invoke-PhpCgi` timeout path (`$outMs` / `$errMs` + running `CopyToAsync` tasks). All wrapped in try/finally with bounded waits on async tasks where applicable.
- **Directory listing exposed hidden + system files** — `Send-DirectoryListing` used `Get-ChildItem -Force`. Dropped the switch so `.env`, `.htaccess`, `desktop.ini`, `Thumbs.db` etc. no longer appear in public indexes by default.
- **`Prefixes` malformed entries failed late with obscure errors** — added explicit startup validation (must end with `/`, must start with `http://`/`https://`). Soft startup warnings for `StaticRoot` / `ErrorPagesRoot` directories that do not exist.

### Added
- **Directory browsing** — new `DirectoryBrowsing` (default `$false`) and `DirectoryBrowsingHidden` (default `@('_error', '.git', '.gitignore')`) configuration keys. When enabled together with `StaticServingEnabled`, requests resolving to a directory with no matching `DefaultDocuments` render an HTML listing of name + size + modified date. Entries named in `DirectoryBrowsingHidden` are omitted (case-insensitive). New `Send-DirectoryListing` helper.

- **Background jobs on interval** — new `BackgroundJobs` configuration key (default `@()`). Each entry is `@{ Path = '<absolute script path>'; IntervalSec = <seconds> }`. Each job runs in its own dedicated runspace + child `pwsh.exe` process on the configured interval; job output is appended to `JobsLogFile` (default `<LogDir>\jobs.log`) — kept separate from request logs. Stopped cleanly during graceful shutdown. Replacement for the legacy PoSH Server `-CustomJob` option.
- **Multi-host / URL-prefix routing** — new `Prefixes` configuration key (default `@()`). When non-empty, overrides the `+`-wildcard binding built from `HttpPort` / `HttpsPort`. Allows hostname-bound listeners (`'https://api.example.com:443/'`) and mixed-port scenarios.
- **IP filter with CIDR and regex support** — `AllowedIPs` and `BlockedIPs` now accept three entry styles in addition to exact matching: CIDR ranges (`'10.0.0.0/8'`) and regex patterns (`'~^192\.168\.'`, leading `~` denotes regex). New `Test-IpMatch` function consolidates the matching logic. Backward-compatible: exact-IP strings continue to work unchanged.

- **Custom HTML error pages** — new `CustomErrorPages` (default `$false`) and `ErrorPagesRoot` (default `<WebRoot>\_error`) configuration keys. When enabled and the client's `Accept` header advertises `text/html`, 4xx/5xx responses serve `<ErrorPagesRoot>\<code>.html` instead of the JSON envelope. Clients that prefer JSON still receive the existing envelope — content negotiation is per-request. Missing files fall back gracefully. New `Resolve-ErrorPage` helper; `Send-Response` consults it on every 4xx/5xx response.
- **`ConvertTo-PoshApiXml`** function — builds an XML response envelope compatible with the legacy PoSH Server `New-PoSHAPIXML` helper. `Items` is a hashtable array; output is indented XML ready to write to stdout. Automatically injected into the script's runspace when `ExecutionMode = 'InProcess'`. Subprocess-mode scripts can use `ConvertTo-Xml` from the framework instead.
- **`$script:acceptType`** per-request stash — parallel to `$script:acceptEncoding`, populated from the request's `Accept` header so `Send-Response` can decide whether to substitute an HTML error page without each call site forwarding the header.

- **PHP-CGI handler** — new `PhpCgiEnabled` (default `$false`), `PhpCgiPath` (default `''`), and `PhpCgiTimeoutSec` (default `60`) configuration keys. When enabled, `.php` URLs are routed through an external `php-cgi.exe`: the server builds the CGI/1.1 environment (`REQUEST_METHOD`, `SCRIPT_FILENAME`, `QUERY_STRING`, `CONTENT_LENGTH`, `CONTENT_TYPE`, all request headers as `HTTP_*`), streams POST bodies to PHP's stdin, parses the `Status` / `Content-Type` / `Location` headers from PHP's stdout, and forwards the body verbatim. PHP files resolving under `\Windows\` are refused (legacy PoSH hardening). Startup validates that `PhpCgiPath` exists when the feature is enabled.
- **`Invoke-PhpCgi`** function — handles the CGI/1.1 contract end-to-end including binary-safe header/body split (`\r\n\r\n` or `\n\n` separator) so PHP-generated images or downloads work correctly.

- **Script extension aliases** — new `ScriptExtensionMap` configuration key registers `.ps1` (JSON envelope), `.psxml` (`text/xml`), `.posh` (`text/html`), `.psapi` (`application/xml`) by default. Routes ending in a non-`.ps1` registered extension bypass the JSON envelope and pass the script's stdout through verbatim with the configured Content-Type — legacy PoSH Server parity for HTML/XML endpoints. New `Test-IsScriptPath` and `Get-ScriptContentType` helpers. `Get-ScriptIndex` now lists every registered extension, not just `.ps1`.
- **In-process execution mode** — new `ExecutionMode` configuration key with values `'Subprocess'` (default, existing behavior) and `'InProcess'`. The new mode runs scripts inside a fresh runspace within the server process via `Invoke-ScriptInProcess` — ~400 ms faster per request but exit codes are best-effort and timeouts use `Runspace.Stop()` instead of `Process.Kill()`. Each request gets its own runspace; it is disposed after the call to limit module-state leakage.
- **Request context variables** — new `InjectContextVars` configuration key (default `$false`). When `ExecutionMode = 'InProcess'` AND `InjectContextVars = $true`, webroot scripts receive `$PoSHQuery` (query-string hashtable), `$PoSHPost` (parsed body or raw JSON string), `$PoSHCookies` (raw Cookie header), and `$PoSHHeaders` (full request-headers hashtable) as runspace-injected variables — legacy PoSH Server compatibility.

- **Basic-Auth option** — new `AuthMode` configuration key with values `'ApiKey'` (default, current behavior), `'Basic'` (only `Authorization: Basic <base64>` accepted), and `'Both'` (either credential accepted). On `'Basic'`/`'Both'` failures the response carries `WWW-Authenticate: Basic realm="…"` so browsers display a login dialog. Credentials sourced from new `POSH_BASIC_USER` / `POSH_BASIC_PASS` machine-scope env vars; new `BasicAuthRealm` configuration key (default `'posh'`) controls the realm string. Startup aborts when `AuthMode` requires Basic but the credentials are missing. NTLM / Integrated Windows Auth intentionally out-of-scope (would require `HttpListener.AuthenticationSchemeSelectorDelegate` and conflict with the existing single-listener model).

- **`application/x-www-form-urlencoded` POST bodies** — `Get-BodyParams` now accepts both `application/json` (existing path) and `application/x-www-form-urlencoded` (new). Form bodies are parsed into an ordered hashtable (with `key[]=…` repetition collapsing into arrays), re-serialised as JSON, and stored via the same `Save-PostJson` pipeline — webroot scripts see no difference. New `AcceptedContentTypes` configuration key (default `@('application/json', 'application/x-www-form-urlencoded')`) gates the allowed prefixes.
- **Cookies / sessions** — new `SessionEnabled` (default `$false`) and `SessionCookieName` (default `'POSH-Session-Id'`) configuration keys. When enabled, a fresh GUID-based HttpOnly session cookie is set on requests that did not carry one; the cookie value is forwarded to webroot scripts via the `POSH_SESSION_ID` env var, and the raw `Cookie:` header via `POSH_COOKIES`. The server remains stateless — there is no server-side session store.
- **CORS support** — new `CorsAllowedOrigins`, `CorsAllowedMethods`, `CorsAllowedHeaders`, `CorsAllowCredentials`, and `CorsMaxAgeSec` configuration keys. Origin matching uses exact comparison or `'*'` wildcard. CORS is disabled by default (empty `CorsAllowedOrigins`).
- **OPTIONS preflight handler** — when CORS is enabled and an OPTIONS request carries an allowlisted `Origin`, the server responds with HTTP 204 and the configured `Access-Control-Allow-*` headers, bypassing auth and rate-limiting so browsers can negotiate without an API key. Non-CORS OPTIONS requests still return HTTP 405.
- **Add-CorsHeaders** + **Send-CorsPreflight** functions — applied once per request after auth, so every subsequent response (including 4xx) carries the CORS headers.
- **`-EnvVars` parameter on `Invoke-Script`** — optional hashtable of environment variables to inject into the child `pwsh.exe` process. Used to forward `POSH_COOKIES` and `POSH_SESSION_ID` to webroot scripts; the parent environment is only materialised when at least one entry is provided so the hot path stays zero-cost.

- **Static file serving** — new `StaticServingEnabled` (default `$false`, opt-in), `StaticRoot` (default empty = `WebRoot`), `DefaultDocuments` (default `@('index.html', 'index.htm')`), and `StaticCacheHeaders` (default `$true`) configuration keys. When enabled, non-`.ps1` GET requests resolve a file under `StaticRoot` (with the same path-traversal protection as the `.ps1` branch), serve it with the configured Content-Type, and optionally emit `ETag` + `Last-Modified` for client-side caching. Directory requests try each entry in `DefaultDocuments` in order. POST on a static resource returns HTTP 405. Static responses also participate in GZIP compression (when no `Range` header is present) and report `Vary: Accept-Encoding`.
- **MIME-type map** — new `MimeTypeMap` configuration key with ~50 default entries (text, HTML, CSS, JS, JSON, XML, images PNG/JPEG/GIF/WebP/SVG/ICO/BMP/TIFF, PDF, archives ZIP/RAR/7Z/GZ/TAR, audio MP3/OGG/WAV, video MP4/WebM/MPEG/FLV/WMV, fonts WOFF/WOFF2/EOT/OTF/TTF, WASM). Unknown extensions fall back to `application/octet-stream`. Exposed via the new `Get-MimeType` helper.
- **Byte-range requests** — `Range: bytes=N-M`, `Range: bytes=N-`, and `Range: bytes=-N` (suffix) are honored on static responses with HTTP 206 + `Content-Range`. Multi-range requests fall back to a full 200 response (multipart/byteranges intentionally not implemented). Malformed or out-of-bounds ranges return HTTP 416 with `Content-Range: bytes */<size>`.
- **Conditional GET (RFC 7232)** — `If-None-Match` and `If-Modified-Since` are honored against the ETag (`"<length>-<utcTicksHex>"`) and `Last-Modified` (HTTP-date) headers; a match returns HTTP 304 with no body.
- **MIME-type blacklist** — new `BlockedMimeTypes` configuration key (default `@()`). Static-response MIME types starting with any blacklist entry trigger HTTP 403. Legacy PoSH Server content-filter parity.
- **`Get-MimeType`** function — returns the configured MIME-type for a file extension or `application/octet-stream` as fallback.
- **`Send-StaticFile`** function — serves a file from disk with full RFC-7232 conditional-request support, RFC-7233 byte-range support, MIME-blacklist check, and 64 KB streaming buffer to avoid loading large media files into memory.

- **GZIP response compression** — `GzipEnabled` (default `$true`), `GzipMinBytes` (default `1024`), `GzipMimeTypes` (default JSON/XML/JS/HTML/CSS/text). Responses are compressed only when the client advertises `Accept-Encoding: gzip`, the body size is `>= GzipMinBytes`, and the Content-Type matches one of the configured prefixes. The matching uses `StartsWith` so charsets and parameters are tolerated. Implemented in `Send-Response`; the per-request `Accept-Encoding` header is stashed in `$script:acceptEncoding` so all 13 existing call sites pick it up without forwarding an extra parameter.
- **Hourly log rotation option** — new `LogSchedule` configuration key with values `'Daily'` (default, file = `YYYY-MM-DD.log`) and `'Hourly'` (file = `YYYY-MM-DDTHH.log`). `Remove-OldLogs` is format-agnostic and applies `LogRetentionDays` to either layout.
- **IIS W3C log format option** — new `LogFormat` configuration key with values `'Native'` (default, current pipe-delimited format) and `'IIS-W3C'` (W3C Extended Log File Format with `#Software` / `#Version` / `#Date` / `#Fields` header lines on first write to a new file). Fields: `date time c-ip cs-method cs-uri-stem cs-uri-query sc-status cs(User-Agent) x-request-id`. `Write-Log` derives missing W3C fields from the Native-style `$Request` string as a fallback so the 13 existing call sites need no changes.
- **Log integrity hashes** — new `LogIntegrityHash` configuration key (default `$false`). When `$true`, `Save-LogIntegrityHashes` writes an `.md5` companion file in `md5sum`-compatible format next to every completed log file at startup. The currently-active log file is intentionally skipped so its hash never goes stale; `startup.log` and `jobs.log` are also excluded. Companion `.md5` files are removed alongside their `.log` files in `Remove-OldLogs`.

### Changed
- **POST request handling**: JSON body is no longer parsed into flat `-Key Value` parameters. Instead the raw body is written to `C:\posh\postjson\YYYYMMDD_HHmmss_<requestId>.json` and the absolute file path is passed to the webroot script as `-JsonFilePath`. Nested objects, arrays, and large payloads are fully supported. Query string parameters on POST requests are rejected with HTTP 400.
- `ScriptTimeoutSec` default reduced from `900` (15 min) to `300` (5 min) — scripts running longer than 5 minutes are forcibly terminated and the caller receives HTTP 504.
- `GET /metrics` is now open (no `X-Api-Key` required) and exempt from both per-IP rate limiting (`RateLimitExemptPaths`) and the global throttle (`MinRequestIntervalSec`) — same treatment as `GET /health`. `RateLimitExemptPaths` default updated from `@('/health')` to `@('/health', '/metrics')`.

### Added
- **`PostJsonDir`** configuration key (`C:\posh\postjson` by default): directory where POST body JSON files are stored. Created automatically at startup.
- **`PostJsonRetentionDays`** configuration key (`30` by default): POST JSON files older than N days are deleted at startup. `0` disables cleanup.
- **`Remove-OldPostJsonFiles`** function: deletes `.json` files in `PostJsonDir` older than `PostJsonRetentionDays` days. Runs at startup, result logged to `startup.log`.
- **`Save-PostJson`** function: writes the raw POST body UTF-8 to a timestamped, request-ID-correlated file in `PostJsonDir`. File name format: `YYYYMMDD_HHmmss_<requestId>.json`.
- **`webroot\post-example.ps1`**: example script demonstrating the JSON file passthrough pattern — reads and parses `-JsonFilePath`, accesses scalar fields, nested objects, and arrays.
- **`docs/post-json.md`**: full documentation for the POST JSON file passthrough feature including concept, script pattern, `curl` and `Invoke-RestMethod` test examples, configuration reference, and error table.
- **Rate-limit table cleanup** at startup: `Remove-StaleRateLimitEntries` removes per-IP entries from `$script:rateLimitTable` whose penalty has expired and whose rate-limit window has elapsed. Prevents unbounded memory growth during long uptimes with many distinct client IPs. Skipped when `RateLimitRequests = 0`. Result logged to `startup.log`.
- **`GET /metrics`** built-in endpoint (open): returns `{ "uptime", "requestsTotal", "rateLimitedTotal" }`. `rateLimitedTotal` counts per-IP rate-limit rejections (HTTP 429 from `Test-RateLimit`); global-throttle 429s (`MinRequestIntervalSec`, main thread) are intentionally excluded. Logged as `METRICS`.
- **Rate limiting** — per-IP Fixed Window rate limiter (`RateLimitRequests = 100` per `RateLimitWindowSec = 600`). Violations receive HTTP 429 with a `Retry-After` header. After the first violation, a flat penalty period blocks the IP for `RateLimitPenaltySec = 1800` seconds. Supports `'reject'` (immediate, default) and `'queue'` (wait up to `RateLimitQueueTimeoutSec`) modes. Configurable exempt paths via `RateLimitExemptPaths`. Separate atomic counter `$script:rateLimitedTotal`.
- **Global request throttle** (`MinRequestIntervalSec = 1`): requests arriving faster than 1 per second receive HTTP 429 with a `Retry-After` header. Enforced in the main thread before any runspace is started — the RunspacePool is never touched for throttled requests. `GET /health` and `GET /metrics` are always exempt. Throttled requests are **not logged** (file I/O in the main thread under burst traffic blocks `GetContext()`).
- **IP filter** (`AllowedIPs` / `BlockedIPs`): checked in the main thread before the global throttle. `BlockedIPs` always rejects with HTTP 403; `AllowedIPs` non-empty restricts access to listed IPs only. `GET /health` is always exempt. Rejections logged via direct `[System.IO.File]::AppendAllText`.
- **`X-Request-Id` response header**: every response (including error responses and IP-filter rejections) includes an 8-character hex request ID. The same value is written as the 6th column in `Write-Log`, allowing clients to correlate HTTP responses to log lines. Global-throttle 429 responses carry `X-Request-Id` but are not logged.
- HTTPS support via `System.Net.HttpListener` with `https://+:<port>/` prefix. Enabled with `-HttpsEnabled` switch; requires a `netsh http sslcert` binding for the configured port.
- `Register-ScheduledTask.ps1` HTTPS setup flow: interactive prompts for certificate source (new self-signed, existing thumbprint, or PFX import), `netsh http add sslcert` binding, optional Windows Firewall rules, and optional HTTP disable.
- Self-signed certificate creation with full SAN support: machine hostname, `localhost`, `127.0.0.1`, and all local IPv4 addresses included automatically via `-TextExtension`.
- `POSH_CERT_THUMBPRINT` system environment variable set after successful certificate binding — for diagnostics only, not a secret.
- `-HttpPort`, `-HttpsEnabled`, `-HttpsPort` parameters on `Start-WebServer.ps1` — HTTP/HTTPS ports and HTTPS activation are now runtime parameters instead of hardcoded values.
- Startup validation: when `-HttpsEnabled` is set, `Start-WebServer.ps1` verifies the `netsh sslcert` binding exists before starting the listener. Exits with `exit 1` and a clear error message if the binding is missing.

### Changed
- **Concurrency architecture**: `Start-ThreadJob` replaced by `RunspacePool` + `[PowerShell]::Create()` + `BeginInvoke()`. Root cause of all previous crashes: `Start-ThreadJob` serialises `-ArgumentList` → live .NET objects become dead `Deserialized.*` snapshots; `$using:` on ScriptBlock-variables resolves to `$null` in PS 7.6; `JobSourceAdapter` degrades under rapid repeated invocations. `RunspacePool` with `InitialSessionState::CreateDefault2()` (minimal ISS) and `InitialSessionState.Variables` injects live objects directly into every runspace — no serialisation, no `JobSourceAdapter`, no shared module state contention.
- `$baseDir` moved before the PowerShell version check — the early-exit log path uses `Join-Path $baseDir 'logs'` instead of a separate hardcoded string.

### Fixed
- `InitialSessionState::CreateDefault()` replaced with `CreateDefault2()` — eliminates auto-module-loading and shared module state contention under rapid RunspacePool load in PS 7.6. Under sustained burst traffic, `CreateDefault()` caused worker runspaces to start silently without executing any code, and eventually corrupted the main runspace's cmdlet registry.
- `GetAwaiter().GetResult()` on stdout/stderr stream tasks blocked forever under load. Root cause: `pwsh.exe` startup takes 3-10s under process-creation contention. Second `WaitForExit(2000)` timed out while process still running — `GetResult()` blocked indefinitely, semaphore slot held, server hung permanently. Fix: second `WaitForExit` raised to 10000ms; `GetResult()` replaced with `Task.WaitAll(..., 5000)` + `IsCompleted` guard.
- Server hang under sustained load: (1) `[PowerShell]` instances created per request were never `EndInvoke()`+`Dispose()`'d — RunspacePool slots leaked. Fix: track `(Ps, Handle)` pairs in `$psInstances`; dispose completed instances each loop iteration. (2) Second `$proc.WaitForExit()` without timeout blocked forever under process-creation contention. Fix: `$proc.WaitForExit(10000)`.
- `[datetime]` `-` operator and `.Subtract()` both fail in RunspacePool runspace contexts (PS 7.x); replaced all occurrences in `Test-RateLimit` with Ticks arithmetic.
- `Register-ScheduledTask.ps1`: `$input` (PowerShell automatic variable) renamed to `$raw` in `Read-HostWithDefault` and `Read-YesNo` — removes `PSAvoidAssignmentToAutomaticVariable` PSScriptAnalyzer warning.
- `webroot\script1.ps1`: `Get-CimInstance Win32_OperatingSystem` and `Get-CimInstance Win32_Processor` now pass `-ComputerName $ComputerName` — previously both always queried the local machine regardless of the parameter value.
- `webroot\script1.ps1` + `webroot\subdir\script2.ps1`: All German strings, comments, and output messages translated to English.
- `netsh http add sslcert` binding in `Register-ScheduledTask.ps1` now correctly deletes any existing binding before adding the new one — previously the delete was silently ignored, causing `add` to fail with error 183 (`ERROR_ALREADY_EXISTS`) on re-installation.
- HTTPS startup validation in `Start-WebServer.ps1` now checks for `IP:Port` in `netsh` output instead of `Certificate Hash` — the latter is locale-specific and absent on non-English Windows installations.

## 2026-04

### Added
- POST request support for webroot script endpoints — scripts can now be called via `POST` with a flat JSON object as the request body. Body parameters are passed to the script identically to query string parameters; body keys take precedence when the same key appears in both. `Content-Type: application/json` is required. Built-in endpoints (`GET /` and `GET /health`) continue to accept GET only.
- `MaxRequestBodyBytes` configuration key (default: `20MB`) — POST request bodies exceeding this limit are rejected with HTTP 413. Bodies with an unknown size are validated after reading.
- HTTP 413 response when a POST body exceeds `MaxRequestBodyBytes`.
- HTTP 415 response when a POST request is made with a `Content-Type` other than `application/json`.
- API key authentication via `X-Api-Key` request header — all endpoints except `GET /health` now require a valid key. The key is configured via the `POSH_API_KEY` system environment variable, set automatically by `Register-ScheduledTask.ps1`.
- `Register-ScheduledTask.ps1` now prompts for the API key and stores it as a `Machine`-scope system environment variable during task registration.
- Health-check endpoint `GET /health` — returns server status, uptime since last start, and total completed script request count. No authentication required, no webroot script needed.
- Log rotation on startup: log files older than `LogRetentionDays` days (default: 180) are deleted automatically when the server starts. Set `LogRetentionDays = 0` to disable.
- Script execution timeout (`ScriptTimeoutSec = 900`): scripts running longer than 15 minutes are terminated and the caller receives HTTP 504 instead of waiting indefinitely.
- HTTP 503 response when the concurrent request limit is exceeded — returned directly from the main loop without consuming a thread slot.
- `AGENTS.md` — full agent-facing documentation covering architecture, deployment, code style, naming conventions, and error-handling strategies.

### Changed
- Concurrency architecture replaced: `RunspacePool` + `BeginGetContext` + `[System.AsyncCallback]` replaced by a `while` loop with synchronous `GetContext()` and `Start-ThreadJob` per request — eliminates `PSInvalidOperationException` crashes caused by ScriptBlock delegates running on .NET ThreadPool threads without a PowerShell runspace (PS 7.4+).
- Webroot scripts now executed as a separate `pwsh.exe` process via `System.Diagnostics.Process` instead of `Start-ThreadJob` inside a running job — `Start-ThreadJob` nested inside a `Start-ThreadJob` fails with `JobSourceAdapter not registered`; `$proc.ExitCode` is the only reliable way to read `exit 0`/`exit 1`.
- Stdout and stderr now read via `ReadToEndAsync()` before `WaitForExit()` — prevents deadlock when the child process fills its output buffer.
- `Register-ScheduledTask.ps1` now runs the server via `pwsh.exe` (PowerShell 7) instead of `powershell.exe` (Windows PowerShell 5.1).
- Scheduled Task now runs under a configurable local administrator account instead of `SYSTEM` — required because GPU access and network authentication do not function correctly under `SYSTEM`.
- Password variable in `Register-ScheduledTask.ps1` is zeroed from memory in a `finally` block — previously zeroed in `try` and `catch` separately, leaving a gap if an unexpected error occurred between decryption and use.
- `Start-WebServer.ps1` now requires PowerShell 7 (`#Requires -Version 7.0`) — PowerShell 5.1 is no longer supported.
- HTTP 405 now covers all non-GET/POST methods — previously only non-GET requests were rejected.
- `Get-ScriptIndex` rewritten as a single `if/else` expression — eliminates an unnecessary initial assignment that was immediately overwritten.
- Shutdown sequence now stops the `HttpListener` before the 5-second grace period — prevents a race condition where callbacks could access already-disposed objects.

### Fixed
- `$cfg.ApiKey` was always `$null` because `$env:POSH_API_KEY` was read after `$cfg` was defined — moved the environment variable read to before the `$cfg` hashtable definition so the value is available at evaluation time.
- `Write-Log`: `ReleaseMutex()` is now only called when `WaitOne()` returned `$true` — calling it from a thread that does not hold the mutex caused an `ApplicationException`.
- `Invoke-Script`: job state is now read into a local variable before `Remove-Job` is called — previously `$job.ChildJobs[0]` was accessed after the job object was already removed, causing a null reference error.
- `Get-ScriptIndex` now wraps its result in `@(...)` before serialising — empty arrays lost their array type in the pipeline and serialised as `null` instead of `[]`.
- `script1.ps1`: `Get-CimInstance Win32_OperatingSystem` called once and stored — previously called twice, wasting a WMI round-trip.
